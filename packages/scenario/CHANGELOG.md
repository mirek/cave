## 0.36.0

### Minor Changes

- b3f5de7: Guard scenario materialization against concurrent changes, including backdated imports, and report a retryable snapshot-changed error before invoking evaluators.
- b3f5de7: Reject overlapping or non-string scenario Boolean mappings before database access, including collisions with default values.
- b3f5de7: Deeply freeze bound scenario input records before evaluator handoff, preserving digest integrity without freezing caller-owned definitions.
- b3f5de7: Require scenario IDs, binding IDs and model digests to be strings before database access, preventing coercible binding IDs from sharing an input slot.
- b3f5de7: Reject duplicate directed unit conversions and malformed conversion definitions before scenario reads, preventing order-dependent numeric inputs.
- b3f5de7: Validate scenario transaction and valid-time boundaries before database access, including scenarios with no bindings, and clarify their distinct period semantics.
- b3f5de7: Require governance record payloads and identities and validate action/effect statuses before appending audit records.
- b3f5de7: Require scenario enum domains to be non-empty dense arrays of unique strings, preventing accidental substring membership and malformed empty-result definitions.
- b3f5de7: Reject mismatched, missing and unknown artifact schemas before recording transactions so callers cannot bypass predecessor checks through another recording entry point.
- b3f5de7: Validate supplied scenario selections as strings naming variables bound by their CAVE-Q patterns before reading the store. Optional inputs with no rows now reject misspelled selections as invalid definitions instead of silently omitting the input. Subject, verb, object and attribute value variables remain selectable, and Boolean existence inputs may still omit select.
- b3f5de7: Require evaluator identity, explicit output and a matching input content digest before persisting external evaluation records.
- b3f5de7: Add a definition digest to frozen scenario inputs and verify both definition and input content before producing explanation provenance. Legacy records require rebinding for verified explanation conversion.
